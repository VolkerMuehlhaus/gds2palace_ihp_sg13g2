# More Examples

These are extra, more advanced gds2palace examples, beyond the basic scripts in [`../workflow`](../workflow). Each folder has its own GDS, XML and scripts, plus a README with the details (the Elmer thermal workflow has its own guide instead).

New to gds2palace? Start with [`../workflow`](../workflow), then pick the how-to example closest to your task. Before you trust absolute numbers from your own model, read the accuracy studies in the order given below.

## How to: features and workflows

### Stackup

| Example | What it shows |
|---|---|
| [`XML_stackup_format_examples`](XML_stackup_format_examples) | Step-by-step tour of the XML stackup format: absolute positions, then positions relative to other layers, then `<Variables>` and expressions, then `<DerivedLayers>` and `<Tables>` |
| [`derived_layers_and_resistors`](derived_layers_and_resistors) | Simulating an IHP SG13G2 `Rsil` resistor. The resistor is detected with `<DerivedLayers>` boolean operations. Also shows how to override stackup `<Variable>`s from Python |
| [`EM_temperature_coefficient`](EM_temperature_coefficient) | Metal conductivity that depends on temperature, using stackup `<Variables>` and expressions: `sigma(T) = sigma(T0) / [1 + TC1*(T-T0)]` for Metal1-5, TopMetal1 and TopMetal2 |

### Ports and de-embedding

| Example | What it shows |
|---|---|
| [`calibrated_boxwall_ports`](calibrated_boxwall_ports) | Beginner's step-by-step guide to calibrated box wall ports (double delay, after J. C. Rautio and V. I. Okhmatovski): an RF MIM capacitor without its feed lines and port parasitics, reference planes at the pcell pins, compared with the PDK model `cap_rfcmim` |
| [`core_transistor_3port_bce`](core_transistor_3port_bce) | Parasitic network of a transistor with 5 ports: 2 via ports at the RF pads, plus 3 via ports directly at the base, collector and emitter, referenced to an artificial ground plane |

## Accuracy: setting up a model you can trust

These studies measure how a model setting changes the result, on real IHP structures. They are listed in the order you would decide those settings: first where the model ends, then how fine to mesh inside it, then how to model the conductors and the stackup, and finally a check against measurement.

| Step | Study | Question it answers |
|---|---|---|
| 1. Simulation boundary | [`simulation_boundary`](simulation_boundary) | How far the absorbing boundary must be from a coil, to the sides and above and below. A small inductor with ground frame and a larger coil without one, each solved with Palace 0.18.1 and 0.19 |
| 2. Mesh size, FEM order, AMR | [`mesh_convergence`](mesh_convergence) | How fine to mesh, whether FEM order 1 or 3 helps, and what adaptive mesh refinement (AMR) costs. A summary page with practical advice, based on six studies (below) |
| 3. Conductor model | [`conductor_models`](conductor_models) | Accuracy and cost of `settings['conductor_model']` = `'surface'`, `'solve_inside'` and `'solve_inside_skin'` on coils, baluns, straight lines and a measured inductor: which one to use for which figure of merit |
| 4. Stackup detail | [`conformal_3D_passivation`](conformal_3D_passivation) | How much a conformal passivation stackup changes the result of a D-band balun compared to the planar stackup |
| 5. Check against measurement | [`measured_vs_simulated/more_accurate_models_L6n2_v5`](measured_vs_simulated/more_accurate_models_L6n2_v5) | A 4-turn inductor, simulated L, Q and SRF compared to measurement in 12 model variants: via array merging with `fill_factor_correction`, conductors as volumes, conformal passivation and the simulation margin. Its README links the earlier versions of this study |

The six mesh studies behind step 2:

| Study | Structure |
|---|---|
| [`mesh_convergence_inductor`](mesh_convergence/mesh_convergence_inductor) | 2-port spiral inductor. Also compares FEM order 1 and order 2 |
| [`mesh_convergence_transformer`](mesh_convergence/mesh_convergence_transformer) | 5-port transformer with center tap, for 30 GHz |
| [`mesh_convergence_D-band_balun`](mesh_convergence/mesh_convergence_D-band_balun) | Edge-coupled balun for 140-170 GHz. The most tightly coupled structure, where the mesh matters most. Follow-up study [`amr_conformal`](mesh_convergence/mesh_convergence_D-band_balun/amr_conformal) on AMR settings |
| [`mesh_convergence_balun2x1`](mesh_convergence/mesh_convergence_balun2x1) | 2:1 edge-coupled balun. Also compares FEM order 1 and order 2 |
| [`mesh_convergence_balun_mim`](mesh_convergence/mesh_convergence_balun_mim) | 3-port balun for 17-22 GHz, with its MIM capacitors included |
| [`mesh_convergence_mom_cmos5l`](mesh_convergence/mesh_convergence_mom_cmos5l) | MOM capacitor on the SG13CMOS5L stackup. Compares FEM order 2 and order 3 |

## Design questions

These studies are about the layout itself, not about simulation settings.

| Study | Question it answers |
|---|---|
| [`ground_cutout_inductor`](ground_cutout_inductor) | How far a ground frame should be from an inductor, and what a solid plane without a cutout costs. Sweeps the frame distance from 30 to 150 µm for a 0.5 nH and a 2 nH coil, and compares floating frame, substrate tie and solid Metal1 or Metal3 plane. (The frame is part of the device; for the distance to the simulation boundary, see `simulation_boundary`.) |

See the top-level [`README.md`](../README.md) for system requirements. The workflow builds Palace model files on any platform, but the Palace solver itself only runs on Linux.
