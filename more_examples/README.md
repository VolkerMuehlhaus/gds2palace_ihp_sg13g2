# More Examples

These are extra, more advanced gds2palace examples. Each one shows a specific feature or workflow that goes beyond the basic scripts in [`../workflow`](../workflow) (`palace_core.py` and others). Each folder has its own GDS, XML and scripts, plus a README with the details. The Elmer thermal workflow has its own guide instead of a README.

## Features and workflows

| Example | What it shows |
|---|---|
| [`core_transistor_3port_bce`](core_transistor_3port_bce) | Parasitic network of a transistor with 5 ports: 2 via ports at the RF pads, plus 3 via ports directly at the base, collector and emitter, referenced to an artificial ground plane |
| [`derived_layers_and_resistors`](derived_layers_and_resistors) | Simulating an IHP SG13G2 `Rsil` resistor. The resistor is detected with `<DerivedLayers>` boolean operations. Also shows how to override stackup `<Variable>`s from Python |
| [`EM_temperature_coefficient`](EM_temperature_coefficient) | Metal conductivity that depends on temperature, using stackup `<Variables>` and expressions: `sigma(T) = sigma(T0) / [1 + TC1*(T-T0)]` for Metal1-5, TopMetal1 and TopMetal2 |
| [`inductor_synthesis_no_external_library`](inductor_synthesis_no_external_library) | Automatic inductor design for a target L and frequency. The layout is generated by code, no external library needed |
| [`inductor_synthesis_using_pclab_library`](inductor_synthesis_using_pclab_library) | Same automatic inductor design, but using the external [pcLab](https://github.com/dgrujic/pcLab) library to generate the layout |
| [`thermal_simulation_using_Elmer`](thermal_simulation_using_Elmer) | Steady-state thermal simulation with Elmer FEM, from GDSII and stackup to result. Works both as a script and with setupThermal |
| [`XML_stackup_format_examples`](XML_stackup_format_examples) | Step-by-step tour of the XML stackup format: absolute positions, then positions relative to other layers, then `<Variables>` and expressions, then `<DerivedLayers>` and `<Tables>` |

## Simulation compared to measurement

| Example | What it shows |
|---|---|
| [`measured_vs_simulated/inductor_L6n2_filledmetals_passivation3D`](measured_vs_simulated/inductor_L6n2_filledmetals_passivation3D) | A 4-turn inductor, simulated L, Q and R compared to measurement. Compares a planar and a conformal passivation stackup, surface impedance and `filled_metals` (solid metal volumes), and mesh sizes from 5 to 1 µm. Also shows a cheaper "passicut" stackup that gets almost the same accuracy as the conformal one |

## Mesh convergence

The [`mesh_convergence`](mesh_convergence) folder has a summary page with practical advice on mesh size, FEM order and adaptive mesh refinement (AMR). It is based on these studies:

| Study | Structure |
|---|---|
| [`mesh_convergence_inductor`](mesh_convergence/mesh_convergence_inductor) | 2-port spiral inductor. Also compares FEM order 1 and order 2 |
| [`mesh_convergence_transformer`](mesh_convergence/mesh_convergence_transformer) | 5-port transformer with center tap, for 30 GHz |
| [`mesh_convergence_D-band_balun`](mesh_convergence/mesh_convergence_D-band_balun) | Edge-coupled balun for 140-170 GHz. The most tightly coupled structure, where the mesh matters most |
| [`mesh_convergence_balun2x1`](mesh_convergence/mesh_convergence_balun2x1) | 2:1 edge-coupled balun. Also compares FEM order 1 and order 2 |
| [`mesh_convergence_balun_mim`](mesh_convergence/mesh_convergence_balun_mim) | 3-port balun for 17-22 GHz, with its MIM capacitors included |
| [`mesh_convergence_mom_cmos5l`](mesh_convergence/mesh_convergence_mom_cmos5l) | MOM capacitor on the SG13CMOS5L stackup. Compares FEM order 2 and order 3 |
| [`conformal_3D_passivation`](conformal_3D_passivation) | The same D-band balun as above, but with a conformal passivation stackup. Shows how much the passivation shape changes the result compared to the planar stackup |

See the top-level [`README.md`](../README.md) for system requirements. The workflow builds Palace model files on any platform, but the Palace solver itself only runs on Linux.
