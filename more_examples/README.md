# More Examples

Extra, more advanced gds2palace examples, each demonstrating one specific
feature or workflow beyond the baseline scripts in
[`../workflow`](../workflow) (`palace_core.py`, etc.). Each folder is
self-contained (own GDS/XML/script) and has its own README (or, for the
Elmer thermal workflow, a dedicated guide) with the details.

| Example | Demonstrates |
|---|---|
| [`core_transistor_3port_bce`](core_transistor_3port_bce) | 5-port transistor parasitic-extraction network: 2 RF pad via ports plus 3 via ports straight to the Base/Collector/Emitter terminals, referenced to an artificial ground plane |
| [`derived_layers_and_resistors`](derived_layers_and_resistors) | Simulating an IHP SG13G2 `Rsil` resistor recognized via `<DerivedLayers>` boolean operations, plus overriding stackup `<Variable>`s from Python |
| [`EM_temperature_coefficient`](EM_temperature_coefficient) | Temperature-dependent metal conductivity via stackup `<Variables>`/expressions - `sigma(T) = sigma(T0) / [1 + TC1*(T-T0)]` for Metal1-5/TopMetal1/TopMetal2 |
| [`filled_metals_inductor_L2n0`](filled_metals_inductor_L2n0) | `settings['filled_metals']` bulk-conductivity volume-conductor EM modeling vs. the default surface-impedance approach, compared at several mesh sizes on a spiral inductor |
| [`inductor_synthesis_no_external_library`](inductor_synthesis_no_external_library) | Fully automatic inductor synthesis to a target L/frequency, with the layout generated by code - no external geometry library needed |
| [`inductor_synthesis_using_pclab_library`](inductor_synthesis_using_pclab_library) | Same automatic-synthesis idea, using the external [pcLab](https://github.com/dgrujic/pcLab) library for layout generation instead |
| [`mesh_convergence`](mesh_convergence) | Five real mesh-convergence studies (inductor, transformer, two baluns, MIM-loaded balun) distilled into practical mesh-size/FEM-order/AMR recommendations |
| [`thermal_simulation_using_Elmer`](thermal_simulation_using_Elmer) | End-to-end GDSII + stackup → steady-state thermal (Elmer FEM) simulation workflow, scripted and via setupThermal |
| [`XML_stackup_format_examples`](XML_stackup_format_examples) | Tutorial walkthrough of the XML stackup format's feature history: absolute → Reference-relative positioning → `<Variables>`/expressions → `<DerivedLayers>`/`<Tables>` |

See the top-level [`README.md`](../README.md) for system requirements - this
workflow builds Palace model files on any platform, but the Palace solver
itself is Linux-only.
